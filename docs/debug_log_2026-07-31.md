## 一、调试目标

对比 Isaac Lab 与 MuJoCo 中同一 checkpoint 的推理行为，确认 sim2sim 差异是否来自：

- 观测向量或动作向量没有对齐；
- 初始根节点高度不一致；
- 轮毂执行器的力矩限制不一致；
- 物理参数或控制频率不一致。

本次使用的策略为 Stage 3 checkpoint：

```text
model_1998.pt
```

Isaac Lab 使用 `Isaac-WheeledLegged-Stage3-Play-v0`，MuJoCo 使用当前 `asset/wheeled_robot.xml` 和 `scripts/play_mujoco.py`。

## 三、MuJoCo 力矩限制验证

当前 MJCF 中轮毂执行器配置为：

```xml
<velocity name="vel_wheel1" ... forcerange="-5 5" />
<velocity name="vel_wheel2" ... forcerange="-5 5" />
```

本机加载 MJCF 后确认：

```text
vel_wheel1: forcelimited = 1, forcerange = [-5, 5]
vel_wheel2: forcelimited = 1, forcerange = [-5, 5]
```

直接向速度 actuator 输入超过范围的控制量时，MuJoCo 的 `actuator_force` 仍被限制为：

```text
ctrl = 20   -> actuator_force = +5 Nm
ctrl = -20  -> actuator_force = -5 Nm
```

因此，当前 MuJoCo 确实有严格的 `+/-5 Nm` 轮毂力矩限制。

需要注意：真实轮毂电机峰值力矩约为 `2 Nm`，所以当前 MuJoCo 与 Isaac 配置仍不是最终真实执行器参数。

## 四、Isaac 初始高度排查

此前 Play 模式禁用了：

```python
self.events.reset_base = None
```

导致 Play 的初始状态与训练 reset 路径不一致。训练配置中的根节点初始高度为：

```python
init_state.pos = (0.0, 0.0, 0.270)
```

本次已恢复 Play 的 `reset_base`，并把 Play 的位置和速度随机范围全部设置为零，只保留确定性根节点 reset。

服务器输出确认：

```text
Event Manager: contains 1 active terms.
reset_base
```

新的 CSV 首帧：

```text
obs_14 = 0.270000
```

这证明策略在 Play 中收到的初始高度已经是 27 cm，不再是之前的约 77 cm。

因此，训练阶段不存在此前所说的初始自由落体问题。之前的高度异常来自 Play 初始化路径被改动后的行为。

## 五、恢复 reset 后的新现象

恢复 root reset 后，机器人不再从 77 cm 下落，而是从 27 cm 开始被策略驱动向上运动：

```text
t=0.02 s: root_z=0.330 m, vertical_vel=+2.998 m/s
t=0.10 s: root_z=0.538 m, vertical_vel=+2.088 m/s
t=0.12 s: root_z=0.578 m
t=0.14 s: 自动触发 root_height 终止并 reset
```

这说明当前 checkpoint 在 Isaac Play 的初始观测下立即输出了较大的轮速动作，机器人被轮毂驱动抬高，而不是发生自由落体。

首帧轮毂 action 和速度目标约为：

```text
action_4 = 0.877, action_5 = 1.124
wheel target ~= 7.02 rad/s, 8.99 rad/s
```

随后原始 action 继续增大，轮速最高达到 Isaac 配置的 `20 rad/s` 速度上限。

## 六、Isaac 力矩限制异常

新的 CSV 中最大值为：

```text
computed_torque_4 = 14.04 Nm
computed_torque_5 = 17.99 Nm

applied_torque_4 = 14.04 Nm
applied_torque_5 = 17.99 Nm
```

`computed_torque` 与 `applied_torque` 完全相同，并且都超过 Isaac 日志表中显示的 `5 Nm` effort limit。

首帧数值与速度控制器计算一致：

```text
2.0 * 7.02 ~= 14.04 Nm
2.0 * 8.99 ~= 17.99 Nm
```

这说明当前记录的 torque 很可能是速度控制器的限幅前计算值，或者 `effort_limit_sim=5.0` 没有真正限制 `DelayedPDActuator` 的输出。仅凭当前 `applied_torque` 字段，还不能证明 PhysX 最终施加的力矩已经被限制到 5 Nm。

## 七、当前结论

已经确认：

1. Isaac 与 MuJoCo 的 policy observation 都是 34 维；
2. policy action 都是 6 维；
3. MuJoCo 轮毂 actuator 严格限制在 `+/-5 Nm`；
4. Play 恢复 `reset_base` 后，Isaac 初始观测高度为 `0.27 m`；
5. 当前 Isaac 初始高度问题已经排除；
6. 当前最可疑差异是 Isaac 轮毂 actuator 的实际力矩限幅；
7. 真实轮毂电机峰值约为 `2 Nm`，当前两边的 `5 Nm` 也尚未与真实硬件对齐。

## 八、下一步计划

下一步应先确认 Isaac Lab `DelayedPDActuator` 中以下字段的实际语义和生效位置：

- `effort_limit`；
- `effort_limit_sim`；
- `computed_torque`；
- `applied_torque`；
- PhysX view 中最终的 DOF force。

在确认真实施加力矩之前，不继续修改奖励函数、摩擦系数或动作延迟。

确认后，再将 Isaac 和 MuJoCo 的轮毂执行器统一到真实的 `+/-2 Nm`，并重新进行同状态、同动作的对照测试。
